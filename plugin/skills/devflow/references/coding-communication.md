# Focused implementation and concise communication

[Superpowers](../../superpowers/SKILL.md) provides the engineering workflow: clarify genuinely unresolved decisions, plan accepted work, debug root causes, test meaningful behavior, review and verify. Load only the relevant profile and its compatibility policy. Continue the current lifecycle artifacts and authorization. Sequential execution is supported when no subagent tool exists; disclose self-review rather than claiming independent review. Small UI fixes retain the shared UI policy and do not restart brainstorming or trigger a full design process.

For scoped review and security work, use [review coordination](review-security.md) to choose Open Code Review or Security Audit and avoid duplicate review passes.

Load the bundled [Ponytail](../../ponytail/SKILL.md) for implementation, fixes or code review. Read affected callers and reuse the existing architecture; choose the smallest change that meets the agreed requirements. Its full level is the normal coding guidance; ultra is not automatic. A request to build an accepted specification is not permission to shrink that specification. Keep error handling, security, accessibility, meaningful tests and lifecycle evidence. Record a real shortcut's limit and upgrade trigger; do not invent shortcuts or disclaimers to fill a template.

[Caveman](../../caveman/SKILL.md) is a concise communication mode when requested (including a request to be brief). Installing, inspecting or packaging it does not activate it. Preserve the user's language, negations, numbers, commands, paths and evidence. Persisted specifications, acceptance records, code comments and UI text keep normal clear prose. Follow host communication requirements even when the voice prefers silence between tool calls. Do not compress away a failed check, missing dependency or remaining task.

The bundle includes the core Ponytail and Caveman skills, not their repositories' full suites. Caveman ultra/wenyan need separate upstream skills; report that boundary when asked rather than inventing a supported alias. No proxy, hook, compression service, telemetry, account or global mode is configured by the installer. Do not claim token savings without a measured comparison. A status request must reflect the mode actually active in this conversation; no hook state is available merely from these files.

For UI, these rules complement the [UI workflow](ui-workflow.md); they do not replace rendered inspection or interactive acceptance. User requirements, the accepted design and handbook gates remain authoritative. Reuse existing authorization and decisions instead of asking again just because a supporting skill describes a checkpoint.
